# 行情 → 战场：映射规则与可调参数

## 回合（`src/game/battle.ts`）

- 第一次拿到指数时开局，以当前价 P 为中心：
  - `bullsWinAt = P × (1 + halfRange)`
  - `bearsWinAt = P × (1 − halfRange)`
  - 都四舍五入到 0.01。
- 胜负判定：
  - 价格 ≥ `bullsWinAt`：**牛方胜**，攻下了位于 +x 端的熊方基地。
  - 价格 ≤ `bearsWinAt`：**熊方胜**。
- 获胜后进入 `intermissionMs`（6 秒）间歇：
  - 这段时间不再判胜负。
  - 横幅显示胜方，败方基地降旗、换色、升旗，并连环爆炸。
  - 间歇结束后，以**当时的价格**开下一局，价格刻度重建，旗帜复原。
- `progress = (price − bearsWinAt) / (bullsWinAt − bearsWinAt)`，限制在 0 到 1 之间，决定战况条的位置。
- `history` 保留最近 20 局，用于显示比分。

## 战场坐标（`src/game/field.ts`）

- 场地价格范围 = `[bearsWinAt − 0.2R, bullsWinAt + 0.2R]`（R = 回合价格跨度），映射到 x ∈ [−110, 110]。所以两端基地永远在 x = ±78.57。
- 前线：`x = field.x(visualPrice) + frontWave(z, t, amp)`。
  - `frontWave` 是三个正弦波的叠加，幅度 amp 介于 1.4 和 4.0 之间，随主动买卖失衡度变大。
  - `visualPrice` 是平滑后的价格，并限制在场地范围内。
- 价格刻度：`tickStep(10)` 取 1、2、2.5、5、10 乘以 10 的整数次幂，大约 10 个主刻度，每个主刻度之间再分 5 个小刻度。

## 兵力（`src/game/armies.ts → layoutArmies`）

**输入**：

- ±1% 的聚合深度，分桶宽度 = 场地价格跨度 / 110。默认参数下约 $0.15 一桶（ETH 约 $2,700 时）。
- 当前价格、`FieldMap`。
- 参数：`usdPerSoldier`、`usdPerTank`、`frontZoneUsd`，以及 `DEFAULT_LAYOUT`。

**规则**：每一方都**从离价格最近的分桶开始往外**处理（买盘对应牛方，卖盘对应熊方）：

| 分桶位置 | 变成什么 |
| --- | --- |
| 越过当前价，已失效的档位 | 跳过 |
| 越过本方胜利线（比本方基地更靠后） | 计入**储备**（`reserveUsd`）。基地前最多摆 80 名士兵和 8 辆坦克，标签显示 `≈$X · N 名士兵 · M 辆坦克` |
| 离价格 ≤ `frontZoneUsd`（3 个分桶） | 计入**前线**金额，排成贴着战线的士兵排 |
| 场内其他位置 | 先看这一桶是不是挂单墙：≥ `usdPerTank` 就生成坦克（最多 3 辆），每辆坦克从这一桶扣掉 0.6 × `usdPerTank`；剩下的按 `usdPerSoldier` 折算成士兵，零头累积到下一桶，排成方阵 |

**前线排**：

- 共 128 列 × 6 行，列的填充顺序是比特反转序，所以只排了半行时也均匀分布。
- 第 r 行士兵的 x = `front(z) − 方向 × (0.9 + r × 0.62)`，每帧跟着战线移动。

**上限**：

| 项目 | 上限 |
| --- | --- |
| 场内士兵 | 每方 1200 |
| 坦克 | 每方 40 |
| 前线士兵 | 128 × 6 |
| 实例总数（渲染层） | 士兵 5000、坦克 220 |

**单价**（`main.ts`）：

- `usdPerSoldier = niceUsd(max(买方场内深度, 卖方场内深度) / 1100)`，取 1、2、2.5、5 乘以 10 的整数次幂。
- 只有新值和当前值相差超过 2.5 倍才重设，防止方阵频繁重排。
- `usdPerTank = 25 × usdPerSoldier`。
- 实测（2026-10-02，ETH 约 $2,725）：实盘 ±1% 深度每侧约 $25M，约 $10K–$25K 一名士兵。

**单位标识**：`F`（前线）、`S`（方阵）、`T`（坦克）、`R` / `RT`（储备），格式是 `F{队伍}:{序号}`，方阵和坦克是 `S{队伍}:{分桶}:{序号}` 这样。key 稳定，所以：

- 同一个 key 的单位会**走**到新位置。
- 新出现的 key：前线兵从己方后方 7–13 个单位处跑上来，其他单位原地淡入。
- 消失的 key：离战线 4 以内（或者是前线兵）就**阵亡倒地**，否则**撤退缩小消失**。

## 事件 → 战场动作（`src/render/world.ts → onMarketEvent`）

| 事件 | 攻方 | 动作 |
| --- | --- | --- |
| 大额主动买 / 卖 | 买：牛方；卖：熊方 | 攻方挑一个靠近前线的单位开炮（≥$100K 时优先坦克）。炮弹落在战线对面 1.5–6.5 + size 处。<br>size = `clamp((log10(usd) − 4.4) × 1.1, 0.5, 3.6)` |
| 爆仓 | 空头被爆：牛方；多头被爆：熊方 | 重炮从攻方战线后 30–45 处打来，落点在被爆一方阵地纵深 1.5–11.5 + size 处。<br>size = `clamp(log10(usd) − 3.8, 0.5, 3.6)` |
| 期权大单 | 主动方 | 在攻方后方打一颗信号弹 |

- **着弹效果**：爆炸、碎块、焦痕、冲击环、闪光。被击中区域内守方士兵被击倒，2 秒后爬起来；坦克只闪光。镜头离得近时会震动。
- **飘字**：「买入/卖出 $X」或「空头/多头爆仓 $X」。
- **电影镜头特写**：爆仓 ≥$125K，或任何事件 ≥$300K；≥$1M 的事件优先级更高。
- **特效预算**：最多 6 个令牌，每 400ms 补 1 个；≥$250K 的事件不受限。市场流水不受预算影响，每条都显示。

## 前线日常交火

- 每方每秒开火 `min(26, 3 + log10(1 + 每秒主动流量) × 3.5)` 次。
- 射手是前两排中随机一名静止的士兵：播放后坐动画、枪口火光和曳光弹，目标是对面战线附近。
- 每发子弹有 3.5% 的概率击倒一名敌兵。

## 战况播报（`narrate()`，按顺序判断，先命中先返回）

| 条件 | 状态键 | 中文 / 英文 |
| --- | --- | --- |
| 开局不到 8 秒 | `deploying` | 大军正开赴前线 / Armies deploying to the front |
| progress > 0.85 | `bullsStorm` | 牛军猛攻熊方大本营 |
| progress < 0.15 | `bearsStorm` | 熊军猛攻牛方大本营 |
| 20 秒内 progress 上升 > 0.04，且卖方近端深度比 10 秒前少 20% 以上 | `askAbsorbed` | 卖方防线被击穿 |
| 20 秒内 progress 下降 > 0.04，且买方近端深度少 20% 以上 | `bidAbsorbed` | 买方防线被击穿 |
| 上升 > 0.04 | 买卖失衡度 > 0.3 时 `bullsCharging`，否则 `bullsAdvancing` | 牛军发起冲锋 / 稳步推进 |
| 下降 > 0.04 | 失衡度 < −0.3 时 `bearsCharging`，否则 `bearsAdvancing` | 熊军发起冲锋 / 稳步推进 |
| 卖方近端深度增加 25% 以上 | `askReinforced` | 卖方阵地获得增援 |
| 买方近端深度增加 25% 以上 | `bidReinforced` | 买方阵地获得增援 |
| 失衡度 > 0.4 或 < −0.4 | `bullsProbing` / `bearsProbing` | 牛军 / 熊军试探防线 |
| 其他 | `skirmishes` | 前线零星交火 |

- 近端深度 = 价格 ±0.06% 以内的挂单。
- HUD 会防抖：新状态要持续 1 秒、并且当前状态已经显示满 2.5 秒才切换。`deploying` 和两种 `Storm` 状态立即切换。

## 大单阈值的自适应（ETH War 新增，`MarketHub.adaptiveBig`）

ETH 现货在清淡时段（UTC 22–23 点实测）每分钟合并后 ≥$10K 的主动单只有 1–2 笔，市场动态面板会长时间空着。所以默认不用固定阈值：

- 每次结算一笔合并主动单，都把金额记进回看窗口（5 分钟）。
- 每秒重算一次阈值：取窗口内**第 k 大**的金额，k = 目标频率（10 笔/分钟）× 已观察的分钟数（最多 5）。这样窗口内恰好约有 k 笔达到阈值。
- 再夹在 `[下限 $2K, 上限 bigTradeUsd=$10K]` 之间：活跃时段阈值顶在 $10K，和固定阈值一样；清淡时段最低到 $2K。
- 刚打开页面时 k 很小，阈值从上限开始，一两分钟内逐渐下降；市场转活跃时阈值随之回升。
- 面板标题旁显示当前门槛「≥ $X」（`Hud.setBigThreshold`，每秒更新），悬停有说明。
- URL `big=N` 关闭自适应、固定为 N；`big=auto`（或不填）开启。`DEFAULT_MARKET_CONFIG.adaptiveBig` 是 `null`，所以 `verify:feeds` 和单测默认仍是固定阈值。

## 可调参数一览

| 参数 | 默认 | 位置 | 调整的影响 |
| --- | --- | --- | --- |
| 回合半宽 | 0.25%（URL `range`） | `BattleEngine` / `main.ts` | 越小胜负越快；太小会导致单价很低、储备数字很大 |
| 间歇 | 6s | `BattleEngine.opts.intermissionMs` | 庆祝时长 |
| 大单阈值 | 自适应：上限 $10K、下限 $2K、目标 10 笔/分钟、回看 5 分钟；URL `big=N` 改为固定 | `main.ts` → `MarketHub.adaptiveBig` | 越高炮击越少，见下节 |
| 期权阈值 | $500 权利金 | `DEFAULT_MARKET_CONFIG` | 期权流水的数量 |
| 爆仓阈值 | $1K | 同上 | — |
| 离群剔除 | 0.5% | 同上 | 剔除价格异常的交易所 |
| 士兵总量目标 | 场内深度 / 1100 | `main.ts` | 画面密度和性能 |
| 坦克倍数 | 25 × 士兵单价 | `main.ts` | 坦克数量 |
| 前线区宽度 | 3 个分桶 | `main.ts`（`frontZoneUsd`） | 前线排的厚度 |
| 布局上限 | 见 `DEFAULT_LAYOUT` | `armies.ts` | 性能 |
| 特效预算 | 6 个令牌，每 400ms 补 1 | `main.ts` | 爆炸密度 |
| 对射频率 | `3 + log10(1 + flow) × 3.5`，上限 26 | `world.ts → rifleFire` | 前线热闹程度 |

## 相对 Bitcoin Battle 的参数差异

ETH 的成交额和盘口深度大约是 BTC 的一半，所以金额类阈值按比例调低，其余规则完全相同：

| 参数 | Bitcoin Battle | ETH War |
| --- | --- | --- |
| 大单阈值（`big`） | $25K 固定 | 自适应 $2K–$10K（目标 10 笔/分钟，见上节）；`big=N` 固定 |
| 期权权利金阈值 | $1K | $500 |
| 爆仓阈值 | $2K | $1K |
| 优先用坦克开炮 | ≥$200K | ≥$100K |
| 电影镜头特写 | 爆仓 ≥$250K / 任何 ≥$600K / 高优先级 ≥$2M | ≥$125K / ≥$300K / ≥$1M |
| 不受特效预算限制 | ≥$500K | ≥$250K |
| 流水加粗（`.big`） | ≥$250K，爆仓 ≥$100K | ≥$125K，爆仓 ≥$50K |
| 价格变动闪光满强度 | $8（绝对值） | 0.01%（相对值） |
| 深度图最小分桶 | $0.5 | $0.05 |
| 模拟行情起始价 / 数量倍数 | $84,200 / 1 | $2,720 / 20 |
